# TANGO

**Think / Decide — the planning and decision layer for the bonsai agent ecosystem.**

TANGO turns a task into a bounded decision and execution plan. It does not own workflow compilation, agent lifecycle, or concrete tool execution.

## Role

```text
Task / AW
    │
    ▼
  TANGO
  Think / Decide
    │
    ├─ understand task
    ├─ select strategy
    ├─ make bounded decisions
    └─ plan coordination
          │
          ▼
        TAKT
  topology / team / assign
          │
          ▼
       TAMAGO
   agent type → EGG → hatch
          │
          ▼
        PLEGO
     tools / execution
          │
          ▼
       Worklog
```

## Boundary

| Component | Responsibility | TANGO does not own |
|---|---|---|
| **AW** | Task / Plan / WF specification and compilation | — |
| **TANGO** | Thinking, planning, decisions | workflow compilation, runtime execution |
| **TAKT** | Coordination topology, team, assignment, handoff, checkpoint | reasoning |
| **TAMAGO** | Agent types, EGG spawn, hatch, lifecycle | reasoning, workflow compilation |
| **PLEGO** | Concrete tools and execution | planning |
| **Worklog** | History and outcomes | decision making |

TANGO may **wrap and call TAKT** when a plan needs team coordination. TAKT provides the coordination mechanism; TANGO provides the reasoning that chooses how it should be used.

**AW owns Plan → WF compilation.** TANGO can produce a plan, but it does not compile that plan into a runtime workflow.

## Go API

The current Go package keeps the planning pipeline small and deterministic. A pipeline step describes an actor and action; validation prevents empty or duplicate step IDs, and execution returns step state. fileciteturn48file0

```go
steps := []pipeline.Step{
    {ID: "observe", Actor: "github-observatory", Action: "load"},
    {ID: "plan", Actor: "tango", Action: "decide"},
}

if err := pipeline.Validate(steps); err != nil {
    // invalid plan
}

states, err := pipeline.Run(steps)
```

## Design principles

- **Decision, not execution** — TANGO decides what should happen next.
- **Coordination through TAKT** — team assignment and handoff are delegated to TAKT.
- **Agents through TAMAGO** — concrete agent instances are created and managed there.
- **Execution through PLEGO** — tools and external actions stay outside TANGO.
- **AW is source of truth** — TANGO output never becomes a workflow merely by being generated by an LLM.

## Status

TANGO is intentionally a small Go decision layer. Keep cross-layer state and runtime-specific behavior outside this repository unless it is directly required for planning and decision making.
